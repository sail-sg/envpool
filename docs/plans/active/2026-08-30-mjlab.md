# Add the complete pinned MJLab task family

This is a living execution plan. Unchecked milestones are not claims of
supported functionality or successful validation.

## Purpose / Big Picture

Expose all twelve built-in MJLab 1.6.0 training tasks through native EnvPool
C++. Preserve observations, rewards, reset distributions, task transitions,
and camera observations. Python is used only for tooling and the independent
oracle. Cover the default randomization behavior required by issue #432.

The user's acceptance priority is correctness with minimal maintenance cost.
Use bitwise comparison when practical, but do not reproduce upstream CPU
math dispatch or add runtime rendering work solely to eliminate harmless
rounding differences. This supersedes the earlier bitwise-first experiments.

## Surprises & Discoveries

- MJLab's CPU simulation still uses MuJoCo-Warp float32 physics. Substituting
  ordinary C MuJoCo diverged materially over a full Cartpole rollout. Preserve
  the actual backend, using Warp's supported CPU capture and native replay.
- Capture needs qualified module/symbol identities and explicit array fills.
  Generated modules need separate namespaces and thread-local CPU scratch.
  These changes belong in the exporter/native integration, not the oracle.
- Reset synchronization must include randomized model fields and derived
  constants. It is performed only once; separate #432 tests observe native
  resets without state synchronization.
- The camera scene BVH must retain its original pre-reset bounds. Rebuilding
  it after reset changes tie-breaking for coincident surfaces and can change
  actual camera observations. Public rendering must also update tracking
  cameras before generating infinite-plane geometry.
- Warp's overlapping spatial-vector views exposed a real GCC ARM aliasing
  bug that discarded gyroscopic values. Keep `-fno-strict-aliasing` for the
  generated kernels and validate with complete physical rollouts.
- Emulating Torch's SIMD reductions, elementary-math backends, and small
  eigensolver was expensive to maintain. The small eigensolve is used for
  the terrain-normal reward, not physics. Standard math with measured
  float32 tolerances is the simpler intended implementation.
- Identical macOS scene inputs can produce sparse CGL/Metal color changes.
  Repeated drawing did not reliably eliminate them. One image-level error
  criterion is more appropriate than task/seed-specific budgets or extra
  runtime draws.
- The pinned oracle has its own dependency hub. Shared test utilities must
  not introduce core NumPy into the oracle's GL-bootstrap dependencies.
- Generated models can differ slightly across host compilers. Validate and
  publish the same canonical asset bytes, rather than assuming a rebuild
  creates an identical wheel.
- Monitor both host and guest disk capacity during release builds. A host
  disk-full error can corrupt guest build outputs and package caches; verify
  affected artifacts instead of treating a successful restart as recovery.

## Decision Log

- Scope: Cartpole (2), Go1/G1 velocity (4), G1 motion tracking (2), and Yam
  manipulation (4). RGB, depth, and segmentation remain separate IDs. Play
  presets and external task plugins are not additional built-in tasks.
- Keep Python MJLab, Torch, a GPU, and runtime compilation out of EnvPool's
  execution path. Use ahead-of-time Warp CPU kernels and native task logic.
- Keep one pinned official oracle: MJLab 1.6.0, MuJoCo/MuJoCo-Warp 3.11.0,
  Warp 1.14.0, and official Torch 2.9.0 CPU wheels. Do not mix baselines.
- Tracking requires a user motion file, matching the upstream contract. Do
  not bundle a fabricated reference motion or require an online service.
- Offload losslessly shared models/textures/graphs to the fourth asset
  distribution. Package the minimal runtime data and applicable notices.
- Retain inexpensive physics compiler settings and actual correctness fixes;
  remove platform-specific math libraries used only for bitwise matching.
- Do not merge or publish core EnvPool before acceptance is complete. The
  separate authorization to publish the fourth asset package is fulfilled.

## Validation and Acceptance

- Every intended ID, alias, observation/action shape, dtype, and API contract
  is exercised. Unsupported tracking inputs fail clearly.
- Native same-seed replay preserves observations, rewards, flags, and task
  state. #432 covers different seeds, successive resets, parallel streams,
  and independently randomized components in the default configuration.
- Oracle comparisons synchronize once after reset, then use only identical
  external actions through the real episode boundary. Compare every step's
  observations, reward, qpos/qvel, discrete outputs, and sampled images.
- Floating oracle outputs use `rtol=1e-5, atol=1e-6`; shape and dtype must
  match exactly. Discrete outputs remain exact. These bounds still require
  full rollout validation; a tolerance is not evidence that a change is safe.
- Public RGB images remain exact outside macOS. On macOS, each image must
  have maximum color error at most 5 and mean absolute color error at most
  0.01 in 0–255 units. Do not average errors across episodes or vector slots.
- Run native family tests and the full test selection on Linux x64, Linux
  ARM64, macOS ARM64, and Windows x64. Installed Python 3.12/3.13/3.14 wheels
  must pass public tests, native reset checks, and paired rollout validation.
- Run the repository format/lint/clang-tidy and Sphinx/spelling paths. Audit
  wheel size, native dependencies, package licenses, and offloaded assets.
- Hosted test/release jobs must be distinguished from local CI reproductions.
  Any unfinished platform or external blocker keeps the port in progress.
